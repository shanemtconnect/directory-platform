## 1. What this repo is

A cloneable "niche directory" website platform (e.g. wedding venues by city, plumbers by
town). One codebase, many sites. Everything niche-specific lives in
`config/site.config.ts` or seeded database rows, never in a component. Cloning a new
niche = run `pnpm new-site` (interactive wizard), seed, deploy.

Stack: Next.js 16 (App Router, `output: "standalone"`), TypeScript strict, Drizzle +
Postgres 16, Redis-backed ISR via `@fortedigital/nextjs-cache-handler`, Tailwind 4,
Better Auth, Resend, Cloudflare Turnstile, Vitest, Playwright, Docker (multi-stage:
`runner` = web, `worker` = jobs), deployed with Coolify.

Public GitHub: https://github.com/shanemtconnect/directory-platform
Working branch: `review-fixes` (PR #1 → `main`, open, not merged).

## 3. How to work locally

```bash
cd ~/Claude/projects/directory-platform
corepack pnpm install --frozen-lockfile
corepack pnpm db:up            # postgres :5433, redis :6380 (docker compose)
DATABASE_URL=postgres://directory:directory@localhost:5433/directory_dev corepack pnpm db:migrate
DATABASE_URL=postgres://directory:directory@localhost:5433/directory_dev corepack pnpm seed
corepack pnpm test             # unit; uses directory_test with a rollback-per-test harness
corepack pnpm test:e2e         # builds + starts the standalone server on :3200 itself
```

Builds and server runs need these env vars (dev values shown):
```
NEXT_PUBLIC_SITE_URL=http://localhost:3200
DATABASE_URL=postgres://directory:directory@localhost:5433/directory_dev
REDIS_URL=redis://localhost:6380
BETTER_AUTH_SECRET=<any string>   BETTER_AUTH_URL=http://localhost:3200
SITE_ENV=production               # anything else = staging = noindex
```
`bash scripts/reseed-dev.sh` drops and rebuilds `directory_dev` (migrate + seed).
Use a Redis db index other than 0 for experiments (`redis://localhost:6380/5`) — the
ISR cache is shared and a stale entry from another build will confuse you.

## 4. How to deploy

1. Push to `review-fixes` (or `main` after the PR merges; then change the Coolify apps'
   `git_branch`).
2. Trigger: `POST {COOLIFY_BASE}/api/v1/deploy?uuid=<app-uuid>&force=true` with the bearer
   token, for both the web and worker apps. Poll `GET /api/v1/deployments/<deployment_uuid>`.
3. Migrations run inside the web container at boot (`MIGRATE_ON_BOOT=true` in
   `docker-entrypoint.sh`). Do NOT use Coolify's "pre-deployment command": it runs in the
   *previous* container, so it never runs on a first deploy.
4. Seeding a fresh site: temporarily set the Coolify Postgres `is_public=true` with a
   `public_port`, run `DATABASE_URL=<public url> corepack pnpm seed` locally, then set
   `is_public=false`. (The worker image can also seed: `./node_modules/.bin/tsx scripts/seed-cli.ts`,
   but Coolify's API has no exec endpoint.)
5. Container logs: `GET /api/v1/applications/<uuid>/logs?lines=80`.
6. `SITE_ENV` is a **build-time** switch (the noindex header is baked into the routes
   manifest). Going staging → production means changing the env var AND redeploying.

Full runbook: `README.md` (Deploy section) and `docs/CLONING.md`.

## 5. Rules that must not be broken (from the plan's Global Constraints)

1. Never hardcode a niche string ("venue", "wedding") in `app/`, `components/`, `lib/`,
   `worker/`, `scripts/`. Use `siteConfig.entity`. `pnpm check:strings` enforces it.
2. All DB access goes through `lib/db/queries/`; every query takes an explicit `viewer`.
3. Public listing reads use `publishedListings(viewer)` and `publicListingColumns` from
   `lib/db/queries/listings.ts`. Never return a full `listings` row to a non-admin.
4. The city indexing gate: `is_indexable` = `listing_count >= seo.minListingsToIndex AND
   intro_html IS NOT NULL`, computed by `lib/db/queries/indexing.ts`. Call
   `recomputeCityIndexability` after any listing status change. Never hardcode it.
5. Pagination is `/city/page/2` with real `<a href>`, never `?page=`. Reading
   `searchParams` makes a route dynamic and kills ISR.
6. JSON-LD only contains what the page renders. Never emit `aggregateRating`/`review`.
7. Migrations are additive. Generate with `pnpm db:generate`, commit `drizzle/`.
8. Strict TypeScript, no `any`. Tests first for new behaviour.
9. Never `FLUSHALL` Redis db 0; never wipe `directory_dev` while others use it.

## 6. Architecture decisions made today (do not re-litigate)

- **ISR cache keyed by build id** (`nextjs:<BUILD_ID>:` prefix, `lib/cache/build-id.mjs`).
  The cache is cold on every deploy by design: asset hashes and server-action IDs are
  build-specific, and the old "cache survives redeploy" goal served unstyled pages and dead
  forms. The app sweeps other builds' namespaces on boot (`lib/cache/sweep.mjs`).
  `CACHE_NAMESPACE` must differ per site sharing a Redis db index.
- **`STATIC_ASSETS_DIR`** (persistent volume) keeps old `/_next/static` files so clients
  holding an old page keep working during a deploy.
- **Permanent redirects are 308**, not 301 (Next's `permanentRedirect`).
- **Doubled `Location` header** on cold ISR redirects is a Next 16.3.4 bug (it replays
  cache-entry headers through raw `appendHeader`). Patched narrowly in
  `lib/boot/location-header.ts`. Delete when upstream fixes it.
- **Turnstile fails closed in production.** Staging needs a key (test keys are fine).
- **Rate limiting** keys on the last `X-Forwarded-For` hop, falls back to an in-process
  map when Redis is down, and skips unidentifiable clients rather than sharing a bucket.
- **Enquiry/submission notifications** go through a durable `job_queue` table processed
  by the worker (`worker/jobs/notify.ts`), sent with Resend. Owner mail only when the
  listing is claimed.
- **Redirects on slug rename** cover child URLs and update the entity's own slug column.
- **Demo blog posts** live in `content/blog/demo/` and load only when
  `NEXT_PUBLIC_DEMO_MODE=true`.

## 10. Gotchas that cost time today

- Another Claude session was committing to this same checkout. It commits to whatever
  branch is checked out. If you must integrate, do it in a `git worktree`, not by
  switching the main checkout's branch.
- `pnpm install --frozen-lockfile` needs `pnpm-workspace.yaml` `allowBuilds: esbuild: false`
  (pnpm 12 fails on the placeholder).
- Playwright runs against a **production build** on port 3200 and the shared Redis;
  orphaned servers on 3200 block the next run (`lsof -iTCP:3200 -sTCP:LISTEN`).
- Coolify's API masks env values on read; verify by behaviour, not by reading them back.
- Coolify database objects do not expose passwords; create databases with a password you
  choose if you need the URL.
- The vitest suite flakes occasionally under full parallelism on the shared test DB
  (`lib/spam/rate-limit.test.ts`, `worker/lock.test.ts`); rerun with `--no-file-parallelism`.
