## Global Constraints

Same as `2026-09-12-phase-3-4-wave-a.md` (items 21–28) plus the originals. Additionally:

29. **Money is provider-neutral in the schema** (`subscriptions.provider*`, `processed_events`).
    PayPal is the only adapter; Stripe is region-blocked and must not appear. Every webhook handler is
    idempotent via `processed_events(provider, event_id)` unique.
30. **Verification is never a payment side effect.** A subscription activating opens a
    `verification_checks` row (`status='open'`); `listings.claim_status='verified'` is set only when a
    check is `passed` AND a subscription is active. Cancellation/lapse drops `verified` → `claimed`.
31. **Tier is the ranking input** (`lib/db/sort.ts`): billing writes `listings.tier`; nothing else does.
32. **Reviews are real or absent.** No seeded, bought or written reviews; `aggregateRating` only when
    `rating_count > 0` AND the reviews are rendered on the page.
33. Ports 3212–3215 and Redis db 15, 5, 6, 7 (one per task, in order). Test DB `directory_test`.

`lib/email/templates/billing*.ts` + notify kinds, `config/validate.ts` **only** to move `PAYPAL_*` into a
documented "required when billing is enabled" group, `e2e/billing.spec.ts`.
Reuse: `~/Claude/projects/toolkit-plus/src/lib/paypal.ts` (`paypalFetch`, `paypalConfigured`) and
`paypalReconcile.ts` — copy the patterns, adapt to this repo's env names (`PAYPAL_CLIENT_ID`,
`PAYPAL_CLIENT_SECRET`, `PAYPAL_WEBHOOK_ID`, `PAYPAL_ENV=sandbox|live`).

**Requirements:**
1. **Plans.** `lib/billing/plans.ts` maps `siteConfig.tiers` × interval → PayPal plan ids held in env
   (`PAYPAL_PLAN_ESSENTIAL_MONTHLY`, `…_ANNUAL`, `PAYPAL_PLAN_PREMIUM_MONTHLY`, `…_ANNUAL`), plus a
   `scripts/paypal-setup.ts` that creates the product + 4 plans from `siteConfig.tiers` prices and
   prints the env lines (idempotent by plan name; sandbox by default). No trial handling in PayPal
   plans beyond `trialDays` from config.
2. **Checkout** `/checkout/[tier]/[interval]?listing=<id>`: signed-in owner of a claimed listing only
   (owner check via `owner_id = profiles.id`); optional coupon code field validated server-side
   against `coupons` (active, window, tier/interval eligibility, `max_redemptions` with a row-level
   lock so two concurrent redemptions of a `max_redemptions: 1` code cannot both succeed — test it);
   creates a PayPal subscription via API with `plan_overrides` for the discount (percent or fixed on
   the first cycle), stores a `subscriptions` row `status='approval_pending'`, redirects to the PayPal
   approval URL; `/checkout/return` confirms and sets `status='active'` (or waits for the webhook).
3. **Webhooks** `POST /api/webhooks/paypal`: verify the signature via PayPal's verify-webhook-signature
   API (`PAYPAL_WEBHOOK_ID`), idempotent via `processed_events`, handle
   `BILLING.SUBSCRIPTION.ACTIVATED|UPDATED|CANCELLED|SUSPENDED|EXPIRED|PAYMENT.FAILED` and
   `PAYMENT.SALE.COMPLETED`: update `subscriptions` (status, `current_period_end`, `cancel_at_period_end`),
   set `listings.tier`, open a `verification_checks` row on first activation, and on cancel/lapse set
   `claim_status` back to `claimed` if it was `verified`; audit rows; `revalidatePath` for the listing
   and its city. Unknown events → 200 + logged. Tests with recorded fixture payloads and a mocked
   verify call.
4. **Billing page** `/account/billing`: current tier, interval, next billing date, trial end, invoice
   history from `PAYMENT.SALE.COMPLETED` events (`processed_events.payload`), **Cancel** (calls PayPal
   cancel, sets `cancel_at_period_end`), change payment method → PayPal hosted link. Owner-scoped.
5. **Renewal reminders** job: 30/7/0 days before `current_period_end` for active non-cancelling
   subscriptions, one email each (`billing_reminders` dedupe via a `meta` marker on `audit_log` or a
   small additive table — choose and justify), tested by moving `lib/clock` `now()`.
6. **Subscription sync** job (hourly): for `active` rows past `current_period_end + 3 days` with no
   renewal event, call PayPal GET subscription and reconcile (pattern from `paypalReconcile.ts`).
7. When `PAYPAL_CLIENT_ID` is unset: checkout shows "billing not configured" (no 500), webhooks 503,
   jobs skip with a log line.

**Tests:** coupon eligibility + concurrency (real DB), webhook idempotency + each event's state
transition (incl. verified → claimed on cancel), plan mapping, reminders by clock, sync reconcile
with a mocked client, checkout owner gating. e2e: pricing CTA → checkout page renders the plan and
refuses a non-owner (no live PayPal call).
