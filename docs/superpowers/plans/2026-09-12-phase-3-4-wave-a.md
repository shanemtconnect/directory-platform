## Global Constraints (binding on every task)

Same as `2026-09-08-review-fixes.md` §Global Constraints (read that file's section verbatim). Plus:

21. **User references.** Better Auth `user.id` is text; every "who" column in our tables
    (`claims.user_id`, `subscriptions.user_id`, `audit_log.actor_id`, `removal_requests.actioned_by`,
    `claims.decided_by`, `suppressions.created_by`) is a uuid referencing `profiles.id`. Always go
    through `ensureProfile(db, viewer)` in `lib/auth/profile.ts`. Never store `viewer.userId` in a uuid column.
22. **Every admin/owner mutation writes an `audit_log` row** in the same transaction (action, entity, meta, ip).
23. **Admin routes**: `app/admin/layout.tsx` already gates on `viewer.role === "admin"` (404 otherwise).
    Server actions used by admin pages must re-check with `requireAdmin()` from `lib/auth/viewer.ts` —
    the layout is not a security boundary for actions.
24. **Owner routes** (`/account/*`): a signed-in user sees only listings where `listings.owner_id =
    profiles.id` of that user. Query functions enforce it with the viewer, never the page.
25. **Personal data**: claim documents live only in the private bucket (`R2_BUCKET_CLAIM_DOCS`), are read
    via 15-minute presigned GETs from an admin-only route, and every presign writes `audit_log`. When
    `R2_*` env is unset (local/staging today) the document evidence path must be unavailable and say so,
    never fail at runtime.
26. **No new dependencies** without saying why in the report. No SMS provider exists — phone OTP is
    out of scope this wave (leave the enum value; do not build a fake).
27. Ports: 3207–3211 for any server run (one per task, see task); Redis db 10–14 (one per task). Postgres
    `directory_test` for tests (rollback harness, migrated through 0007); dev DB `directory_dev` is shared, read-only.
28. Migrations: additive, generated with `corepack pnpm db:generate`; apply to `directory_test` only; name
    yours in the report (the controller renumbers on merge).

**Requirements:**
1. `/claim/[listing]` (listing resolved by `city/slug` pair or by id — use the id in the URL to avoid
   slug ambiguity: `/claim/<listingId>`; the listing page links there). Requires sign-in (redirect to
   `/login?next=`). Shows the ladder:
   - **Domain email match** (auto): if the listing has a `website` with a domain and the claimant
     supplies a `business_email` on that domain → send a magic link (token, 30-min expiry) to it;
     visiting `/claim/verify/[token]` marks `email_verified_at`, sets `claims.status = 'approved'`,
     `listings.claim_status = 'claimed'`, `listings.owner_id = profiles.id`, `profiles.role = 'owner'`
     (if `user`), audit, and emails the owner (`claimApproved`). Gate met in under 60 s with no admin.
   - **Document** (manual): only when `R2_*` is configured — presigned POST (reuse `lib/media/r2.ts`
     policy shape, bucket `R2_BUCKET_CLAIM_DOCS`, private) for a proof document (PDF/JPG/PNG, 8 MB);
     claim goes `pending` for admin review. When R2 is unset, this option is hidden with a note.
   - Phone OTP: not built (constraint 26); the UI must not offer it.
   One open claim per listing per user; a listing that is already `claimed`/`verified` shows "already
   claimed" and a link to `/report/<id>` (Task 18's route — link only).
2. `/admin/claims`: pending claims list + detail; **Approve**/**Reject (reason)** with audit; document
   links go through `/api/admin/claims/[id]/document` which `requireAdmin()`s, presigns a 15-minute GET,
   writes `audit_log` `claim.document_viewed`, and 302s. Never a public URL.
3. **30-day purge job** (`worker/jobs/purge-claim-docs.ts`): claims decided > 30 days ago with document
   paths → delete objects from R2 (skip when unset), null the paths, set `documents_purged_at`, audit.
   Tested by moving the clock (`lib/clock.ts` `now()` seam).
4. Owner dashboard `/account`: "Your listings" (via `lib/db/queries/owner.ts`, owner-scoped by
   `owner_id = profiles.id`), each linking to `/account/listings/[id]` (edit: description, phone,
   website, socials, opening hours — the tier's `showWebsite` etc. still govern display; saving = audit +
   revalidate the listing path with `revalidatePath`) and `/account/listings/[id]/enquiries` (list,
   mark read/replied — sets `read_at`/`replied_at`/`responded_in_minutes`). Non-owners get 404.
5. Replace the "Claim it free" mailto on the listing page with the real link.
6. e2e (`e2e/claim.spec.ts`): sign up, open `/claim/<id>` for a seeded listing whose website domain you
   set in the spec, request the magic link, read the token from the `job_queue`/DB (the mail sender
   is `not-configured` locally) and visit `/claim/verify/[token]`; assert the listing page now says
   "Claimed by owner" and `/account` lists it.

**Tests:** ladder unit tests (domain match rules: exact domain, subdomain, free-mail domains like
gmail.com are never a match), token expiry, claims queries (owner scoping, admin-only decisions),
purge job with a fake clock and a fake R2 client, owner edit action.
